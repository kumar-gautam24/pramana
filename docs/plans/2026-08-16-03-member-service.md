# Pramana Plan 03 — Member Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `member` service — the system of record the deterministic criterion verifiers query. It holds synthetic members, their coverage, conditions, sleep studies, CPAP usage and clinical notes, and answers precise factual questions about them.

**Architecture:** A FastAPI service owning `pramana_member`. Members come from Synthea's CSV export (demographics, encounters, comorbidities); the sleep domain — studies, AHI, CPAP usage nights, symptom notes — is generated on top, seeded per member so it is deterministic and reproducible. Endpoints answer one factual question each, because a criterion verifier asks one factual question at a time.

**Tech Stack:** Python 3.12, uv, FastAPI, SQLAlchemy async, Alembic, Postgres 16, pytest, ruff.

## Global Constraints

- Python 3.12. Dependencies with `uv`; lockfile committed.
- The service owns `pramana_member` and no other database. No cross-service joins.
- `packages/common` is the only shared import; `member` must not import from another service.
- **No real patient data, ever.** Everything here is synthetic. See `docs/decisions/0012-synthea-substrate-with-a-sleep-layer.md`.
- **No hardcoded per-policy logic.** This service knows nothing about NCD 240.4. It answers factual questions; the adjudication service decides what they mean. See ADR-0003.
- **Generation must be deterministic.** Every generator takes an explicit seed. A golden case that cannot be regenerated byte-for-byte is not a golden case.
- Misconfiguration fails at startup, not on first request — the lifespan probes the database, as `policy` does.
- Comments explain **why**, never what.
- Commits: conventional style, imperative, lowercase subject. **Never any attribution trailer** — no `Co-Authored-By`, no generated-with footer, no model or tool name.
- Tests required on critical paths: eligibility windows, the adherence calculation, generator determinism, and near-miss controllability. CRUD and route wiring are not.
- **Ports are free now.** Postgres on 5432, member service on 8005. No overrides needed.

## What plan 02 established that this plan follows

- Service layout: `services/<name>/{pyproject.toml,Dockerfile,alembic.ini,migrations/,src/<name>/,tests/}`.
- `config.py` exposes `get_settings()` with no default for `database_url`, so a bad configuration fails at import.
- The lifespan runs `SELECT 1` before yielding; `/health` is cheap and dependency-free, `/ready` reflects real dependencies and returns 503 when they are missing.
- Tests use a **separate** database (`pramana_member_test`), declared in `scripts/create-databases.sql`, with a per-test transaction rolled back by a `db_session` fixture.
- Alembic autogenerate does not emit extensions and mis-renders generated columns — read the migration it produces before applying it.

## Why the endpoints look the way they do

NCD 240.4 needs these facts, and nothing else, from a member's record:

| criterion | fact needed |
| --- | --- |
| coverage active on the date of service | coverage window |
| a positive sleep test of an accepted type | study type, date |
| AHI or RDI ≥ 15, or 5–14 | study AHI/RDI, apnea events, recorded hours |
| documented symptoms | narrative notes |
| documented hypertension, ischemic heart disease or history of stroke | conditions before the date of service |
| adherence: ≥4 hours a night on 70% of nights in a 30-day window | CPAP usage nights |

Each endpoint answers exactly one of those. The service never returns a verdict — it returns facts, and `adjudication` decides. That separation is what keeps ADR-0003 honest.

```python
from contextlib import asynccontextmanager

from fastapi import FastAPI
from fastapi.responses import JSONResponse
from sqlalchemy import text

from member.db import engine


async def _probe_database() -> None:
    async with engine.connect() as connection:
        await connection.execute(text("SELECT 1"))


@asynccontextmanager
async def lifespan(app: FastAPI):
    # Fail at startup rather than on the first request: create_async_engine opens no
    # connection, so without this a wrong DATABASE_URL starts cleanly and 500s later.
    await _probe_database()
    yield


app = FastAPI(title="pramana member", lifespan=lifespan)


@app.get("/health")
async def health() -> dict[str, str]:
    return {"status": "ok"}


@app.get("/ready")
async def ready():
    try:
        await _probe_database()
    except Exception:
        return JSONResponse({"status": "unready", "reason": "database"}, status_code=503)
    return JSONResponse({"status": "ready"})
```

### Task 4: Seeded sleep-domain generation

**Files:**
- Create: `services/member/src/member/generate.py`
- Test: `services/member/tests/test_generate.py`

This is the critical path of plan 03. Read ADR-0012 before starting: Synthea has no sleep apnea module, so every clinically decisive fact in this system is authored here. The generator is test apparatus and gets reviewed like it.

**Interfaces:**
- Produces (**pure**, no I/O, no database):
  - `SleepProfile` — frozen: `test_type: str`, `channels: int`, `apnea_events: int`, `recorded_hours: float`, `ahi: float`, `study_date: date`
  - `generate_sleep_profile(member_id: str, seed: int, study_date: date, target: str = "qualifying") -> SleepProfile`
  - `generate_usage_nights(member_id: str, seed: int, start: date, nights: int, target: str = "adherent") -> list[tuple[date, float]]`
  - `TARGETS` — the set of accepted `target` values

`target` selects the *shape* of the case, which is what makes near-miss golden items constructible:

| target | meaning |
| --- | --- |
| `qualifying` | AHI ≥ 15 comfortably |
| `borderline_high` | AHI just at 15 |
| `near_miss_high` | AHI just below 15 — **must not** qualify under set 1 |
| `mild_range` | AHI within 5–14, needing symptoms or a comorbidity |
| `below_threshold` | AHI under 5 |
| `adherent` (usage) | ≥4 hours on comfortably more than 70% of nights |
| `near_miss_adherence` (usage) | ≥4 hours on just under 70% of nights |

- [ ] **Step 1: Write the failing test**

Create `services/member/tests/test_generate.py`:

```python
from datetime import date

import pytest

from member.generate import TARGETS, generate_sleep_profile, generate_usage_nights

STUDY_DATE = date(2026, 1, 10)


def test_generation_is_deterministic():
    """A golden case that cannot be regenerated byte-for-byte is not a golden case."""
    first = generate_sleep_profile("M1", seed=7, study_date=STUDY_DATE)
    second = generate_sleep_profile("M1", seed=7, study_date=STUDY_DATE)

    assert first == second


def test_different_members_get_different_profiles():
    """Seeded on the member as well as the seed, so one population is not 500 copies."""
    a = generate_sleep_profile("M1", seed=7, study_date=STUDY_DATE)
    b = generate_sleep_profile("M2", seed=7, study_date=STUDY_DATE)

    assert a != b


def test_ahi_is_consistent_with_the_raw_counts():
    """AHI is events per hour of recorded sleep. If the derived index disagreed with the
    counts, one criterion would pass and its sibling fail on the same study."""
    profile = generate_sleep_profile("M1", seed=7, study_date=STUDY_DATE)

    assert profile.ahi == pytest.approx(profile.apnea_events / profile.recorded_hours, abs=0.05)


@pytest.mark.parametrize(
    "target,low,high",
    [
        ("qualifying", 15.0, 100.0),
        ("mild_range", 5.0, 14.0),
        ("below_threshold", 0.0, 4.99),
    ],
)
def test_targets_land_in_their_band(target, low, high):
    for member in (f"M{i}" for i in range(30)):
        profile = generate_sleep_profile(member, seed=3, study_date=STUDY_DATE, target=target)
        assert low <= profile.ahi <= high


def test_near_miss_high_is_below_fifteen_but_only_just():
    """ADR-0009: a refusal set of obviously-out-of-scope cases measures the easy half of
    the problem. This is the case that must not be approved and nearly is."""
    for member in (f"M{i}" for i in range(30)):
        profile = generate_sleep_profile(
            member, seed=3, study_date=STUDY_DATE, target="near_miss_high"
        )
        assert 14.0 <= profile.ahi < 15.0


def test_borderline_high_qualifies_exactly_at_the_threshold():
    profile = generate_sleep_profile("M1", seed=3, study_date=STUDY_DATE, target="borderline_high")

    assert profile.ahi == 15.0


def test_an_unknown_target_raises():
    """Silently falling back to a default would produce a golden case that does not test
    what its name says it tests."""
    with pytest.raises(ValueError, match="target"):
        generate_sleep_profile("M1", seed=3, study_date=STUDY_DATE, target="nonsense")


def test_adherent_usage_clears_seventy_percent():
    nights = generate_usage_nights("M1", seed=5, start=date(2026, 2, 1), nights=30)
    qualifying = sum(1 for _, hours in nights if hours >= 4.0)

    assert len(nights) == 30
    assert qualifying / 30 > 0.70


def test_near_miss_adherence_falls_just_short():
    nights = generate_usage_nights(
        "M1", seed=5, start=date(2026, 2, 1), nights=30, target="near_miss_adherence"
    )
    qualifying = sum(1 for _, hours in nights if hours >= 4.0)

    assert 0.60 <= qualifying / 30 < 0.70


def test_usage_nights_are_contiguous_and_unique():
    nights = generate_usage_nights("M1", seed=5, start=date(2026, 2, 1), nights=30)
    days = [night for night, _ in nights]

    assert len(set(days)) == 30
    assert days == sorted(days)


def test_every_target_is_reachable():
    """A target named in TARGETS but unhandled would fail only when a golden case used it."""
    for target in TARGETS:
        assert target
```

- [ ] **Step 3: Write `generate.py`**

Use `random.Random(f"{member_id}:{seed}:{target}")` seeded from a string so the stream depends on the member, the seed and the shape — that is what makes determinism and per-member variation hold together. ### Task 5: Narrative notes

**Interfaces:**

- `SYMPTOMS` — the four NCD 240.4 symptom phrases: excessive daytime sleepiness, impaired cognition, mood disorder, insomnia.

Notes are what the **judgment** criteria read, so they must be prose a model has to interpret, not a checklist it can pattern-match. A note asked to document daytime sleepiness should say something like *"Reports falling asleep watching television most evenings and once while stopped in traffic"* — not *"Symptom: excessive daytime sleepiness."*

That is unavoidable given Synthea's coverage, and it is also what makes near-miss golden cases constructible at all. It must be stated in the README when results are published, because an eval whose difficulty its author chose is a weaker claim than one whose difficulty came from the world.
